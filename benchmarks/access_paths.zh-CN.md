# 专用查询与随机访问路径

[English](access_paths.md) | [简体中文](access_paths.zh-CN.md)

本文是本地版本间微基准，基线 `3e0daa8`，优化版 `3fcda56`。
与 EnTT 的独立重测见[最新报告](ecs_comparison.zh-CN.md)。
测量于 2026-09-21，Windows x64、MSVC 19.50.35724、C++20 Release（/O2）。
两版使用完全相同的 `access_paths.cpp`，不代表完整引擎接入测试。

## 方法

10 万实体，两个 8 字节组件。每个程序运行六轮，舍弃第 0 轮，取第 1–5 轮中位数；先运行基线再运行优化版。
创建包括 Create 和两次 Add，不预留世界或组件池容量；注册和测试程序的实体数组预留不计入创建时间。
各遍历方式更新 200 次；随机 Get 按固定打乱顺序读取十轮（mt19937 种子 20260921）。
增删向所有实体添加第三个组件，再全部移除，重复十轮；销毁移除全部实体。
遍历校验和在计时后计算。分别测试复用查询和每次新建查询，ForEachBatch 单独作为参照。
所有轮次、所有遍历方式的新旧校验和一致。

## 覆盖率回归

两版均使用 `sparse_query.cpp` 的 Where + 校验和负载，并采用相同容量预留。
交替运行六对进程，舍弃第 0 对，取其余五对中位数；每个进程预热 10 次、计时 200 次。
这与上面的纯更新测试不同。

| 覆盖率 | 两版候选量 | 3e0daa8 µs/查询 | 优化后 µs/查询 |
| --- | ---: | ---: | ---: |
| 1% | 1,000 | 5.878 | 2.908 |
| 10% | 10,000 | 73.921 | 31.677 |
| 100% | 100,000 | 572.338 | 270.806 |

校验和全部一致。[原始数据](access_paths_coverage.txt)。本轮不再缩小候选量，而是降低单个候选的处理成本。

## 实现与正确性

- 密集标量查询在行循环外绑定列首地址，去除逐组件重复的存储判断和必选成员检查。每次执行重新绑定，支持执行间扩容。
- 纯稀疏查询按最小池类型分派一次，直接按池内位置取驱动组件，其余池各查找一次。
  标量回调、过滤和 Count 不再查询 archetype/行位置；低层 Visit 因显式要求位置，仍需解析。
- 混合查询保留成员检查，包括仅 Optional 或 Without 引入另一类存储的情形。
- World 内部复用已校验的组件 ID，保留注册与实体代际检查，不新增公开的无检查访问器。

测试覆盖密集可选列、谓词和排除条件、串并行一致性、列重分配、驱动池切换、可选别名、重复必选类型、
排除必选类型、稀疏必选配密集可选、过期句柄、const 访问、缺失组件和未注册错误。
原生命周期、执行间结构变更、覆盖率测试继续启用。回调内结构变更仍不支持。

## 复现

```sh
cmake -S . -B build_sparse_query -DEKIT_BUILD_BOIDS=OFF -DEKIT_BUILD_QUERY_BENCHMARK=ON
cmake --build build_sparse_query --config Release
ctest --test-dir build_sparse_query -C Release --output-on-failure
./build_sparse_query/Release/ekit_access_paths_bench
./build_sparse_query/Release/ekit_sparse_query_bench
```

基线使用相同源码、编译器与参数，替换为 `3e0daa8` 的 include 目录。
这里不要定义 `EKIT_QUERY_BASELINE`：两版均支持容量预留和 CandidateCount，测试准备应保持一致。
